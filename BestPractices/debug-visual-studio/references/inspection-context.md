# Keep Debugger Inspection On The Same Pause And Frame

Pass `includeContext: true` to request frame identity on stack, locals, evaluation, watches, snapshots, and bounded expansion. It defaults to false to keep ordinary responses compact. Composite results return `context` once at the response's value root, not on each expression or section. It contains `stopId`, `generation`, process/thread IDs, frame index/depth, and available function/source position. These fields identify the inspected frame, which can differ from the IDE's selected frame. Frame indices and depths are valid only in that thread at that pause. Recursion is distinguished by depth/index, never by function name. Selected-frame index lookup examines at most 1,024 frames and remains null if unresolved. Missing optional engine fields stay null. Explicit includeContext requires an updated extension; unsupported versions fail rather than silently dropping the requested identity.

Retain `debug_status.stopId` / `generation` and pass them as `expectedStopId` / `expectedGeneration` to `debug_get_callstack`, `debug_get_locals`, `debug_evaluate`, `debug_eval_many`, `watch_add`, `watch_list`, `debug_snapshot`, `debug_wait_for_break`, and `debug_expand` when the investigation must stay on that pause. A changed or resumed context is rejected. An older extension cannot silently ignore these guards. Read current state before retrying; a stale inspection is not a reason to repeat execution.

`debug_get_callstack` can target `threadId` without selecting it. Locals/evaluation/watches can also target a 1-based `stackFrame`; with an explicit thread, it defaults to that thread's first frame. Omit thread/frame to inspect the current selection. Stack response context identifies the inspection frame; each returned stack row has its own `frameIndex`.

Updated extensions evaluate batches and watches in one pinned frame and validate the pause again after collection. Plain current-frame `debug_eval_many` calls remain compatible with older extensions using their legacy evaluation API only when the frame RPC is absent. Available pause identities are checked between legacy results; very old extensions without those identities cannot provide the same atomic guarantee. Explicit thread/frame selectors, stop guards, or `includeContext: true` never use that fallback. A paused watch addition is saved only after inspection completes and its context is validated. Unguarded `watch_add` outside a pause can still save configuration without evaluating it; the result has no inspection context. `watch_list` reports unavailable outside a pause.

Legacy expression evaluation still permits debugger function evaluation and its side effects; shared context does not make those expressions side-effect-free. Use `debug_expand` with its default function-evaluation policy for inspection-only expansion. Source positions alone do not prove source matches the loaded build; use `debug_source_evidence` for checksum comparisons. Parallel/thread-specific legacy summaries remain separate capabilities until explicitly qualified.
